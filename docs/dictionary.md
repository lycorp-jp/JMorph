# Dictionaries

This document describes the dictionaries used by JMorph and the specifications of its supplemental files.

## Supported Dictionaries

JMorph currently supports UTF-8 MeCab-format binary dictionaries. The following layout shows the required and optional files:

```text
dictionary/
├── sys.dic
├── matrix.bin
├── unk.csv
├── dump.unknown   # Required with OutputMode.ALL
└── dump.userdic   # Optional
```

| File | Purpose |
|--|--|
| `sys.dic` | System dictionary containing words, costs, and features |
| `matrix.bin` | Connection costs between left and right context IDs |
| `unk.csv` | Context IDs and costs for unknown-word nodes generated by JMorph |
| `dump.unknown` | Output features for unknown words. Required with `OutputMode.ALL` |
| `dump.userdic` | Optional output features for the request-time user dictionary |

`dump.unknown` is required when using `OutputMode.ALL`. `dump.userdic` is optional; with `OutputMode.ALL`, when it is absent, JMorph generates request-time user dictionary features from `dump.unknown`. Dictionaries and their supplemental files may be subject to licenses different from JMorph's license. Check the terms for use and redistribution.

You can load additional dictionaries with `additionalDic`. Set each `location` to a directory containing `sys.dic`; JMorph loads `<location>/sys.dic`. The additional dictionaries are searched together with `baseDic`, but all dictionaries share the connection matrix loaded from `baseDic.location`. Their left and right context IDs must therefore be compatible with that matrix.

When loading `baseDic` and each `additionalDic`, JMorph checks that the left and right context IDs in `sys.dic` are compatible with `baseDic`'s `matrix.bin`. Loading fails if an ID is invalid.

## Locations

Place the base dictionary's `sys.dic` and `matrix.bin` at `baseDic.location`. Unless separate locations are explicitly configured, JMorph also loads the supplemental files required for unknown-word processing and the request-time user dictionary from `baseDic.location`.

To add a dictionary, set each `additionalDic.location` to a separate directory containing that dictionary's `sys.dic`. Additional dictionaries use the `matrix.bin` from `baseDic.location`, so they do not need their own connection matrix. Their context IDs must be compatible with the base dictionary's matrix.

Relative paths, absolute paths, and `file:`, `jar:`, and `classpath:` formats are supported. See [Configuration](./configuration.md#location) for details.

## `unk.csv`

This CSV file defines connection information for unknown-word nodes.

```text
surface form,left context ID,right context ID,cost,category ID,reserved
```

```csv
UNK,1,1,10000,1,1
```

| Field | Description |
|--|--|
| Surface form | Must be `UNK` |
| Left context ID, right context ID | IDs corresponding to the connection matrix in `matrix.bin` |
| Cost | Higher values make the unknown-word candidate less likely to be selected |
| Category ID | Specify `1`. JMorph uses the row whose category ID is `1` |
| Reserved | Currently unused. Specify `1` for compatibility |

Appropriate cost values depend on the system dictionary and use case. Analyze real input and tune the values while checking how candidates are selected relative to known words.

## `dump.unknown`

This file defines output features for unknown words by character type. Each line contains a key and a feature template separated by a comma. Fields within the feature template are separated by the configured `delim`, which defaults to an ASCII space.

```text
<key>,<feature template>
```

| Key | Character type | Examples |
|--|--|--|
| `o` | Other, symbols, and special characters | `◆`, `.` |
| `a` | Half-width and full-width letters | `HTML`, `ＡＢＣ` |
| `c` | Kanji | `水`, `東京` |
| `k` | Katakana | `テスト` |
| `h` | Hiragana | `あいうえお` |
| `n` | Half-width and full-width Arabic numerals | `123`, `２０２５` |
| `N` | Kanji numerals | `百二十三` |

The `o` definition is required because it is used for character types without a matching key. The katakana middle dot `・` is treated as `o`, not katakana.

```text
o,補助記号 一般 * * * *
a,名詞 普通名詞 一般 * * *
c,名詞 普通名詞 一般 * * *
k,名詞 普通名詞 一般 * * *
h,名詞 普通名詞 一般 * * *
n,名詞 数詞 * * * *
N,名詞 数詞 * * * *
```

Feature templates support `%s` and `%y`. For unknown words, both placeholders expand to the surface form.

Match the number and meaning of feature columns to `sys.dic`.

## `dump.userdic`

This file defines output features for the request-time user dictionary. The key is always `u`.

```text
u,<feature template>
```

```text
u,名詞 普通名詞 一般 * * * %s %y
```

| Placeholder | Expansion |
|--|--|
| `%s` | Surface form |
| `%y` | The specified reading, or the surface form when no reading is specified |

With `OutputMode.ALL`, if `dump.userdic` does not exist, JMorph uses the definition in `dump.unknown` that corresponds to the first character of the surface form. If no definition exists for that character type, it falls back to `o`.

## Delimiter Constraints

`unknownDic.delim` and `userDicInRequestProvider.delim` must each be exactly one character encoded as one byte in UTF-8. Normally, use the default ASCII space. Feature templates must not contain commas.
